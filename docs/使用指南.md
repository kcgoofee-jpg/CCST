# 使用指南

[README](../README.md) 的详细版。先看下面「四样东西」和「三种用法」，找到自己的那一种，再跳到对应章节。

## 四样东西

CCST 由四样东西组成，不同用法用到的不一样：

| 东西 | 是什么 | 在哪 |
| --- | --- | --- |
| 面板 | 酒馆里的扩展：切模型、思考深度、状态、连接引导 | 浏览器里的酒馆 / TauriTavern 手机 App |
| 代理（插件或独立） | 把酒馆的请求转给 Claude，负责缓存排布、防丢回复、额度统计。两种跑法：作为**酒馆服务器插件**随酒馆启动；或**独立运行**（`npm start`、Mac 酒馆工具、服务器脚本、Docker） | 电脑 / 服务器 |
| 一键安装器 | 双击一下把代理装成原版酒馆的服务器插件（`installer/`：Mac `.command`、Windows `.bat`） | 只用于原版酒馆 |
| Mac 酒馆工具 | Mac 上的启动菜单（`launcher/`）：启动 / 重启独立代理、手机模式、查状态、登录 | 只用于用法二 |

## 三种用法

| | 用法一 原版酒馆 | 用法二 TauriTavern 与手机 | 用法三 服务器与 Docker |
| --- | --- | --- | --- |
| 酒馆在哪 | 你的电脑（Chrome / Edge） | 手机或 Mac 上的 TauriTavern | 云服务器 |
| 代理怎么跑 | 酒馆服务器插件 | 电脑上独立运行（开手机模式） | 服务器上独立运行，或当酒馆插件 |
| 怎么装 | 一键安装器 | 酒馆工具 / `npm start` + 面板按链接安装 | `deploy/install.sh` / Docker |
| 状态 | 主线，持续维护 | 能用，同步冻结 | 能用，安装脚本和 Docker 由 CI 自动测试 |

**用法一 原版酒馆**：这是主线。一键安装器把代理装进酒馆的 `plugins/`，代理随酒馆启动，面板通过扩展装上；没有启动器，也没有手机模式。

```
 浏览器（酒馆 + 面板）──▶ SillyTavern ──(服务器插件 = 代理)──▶ Claude
                        └────────── 同一台电脑，同一个进程 ──────────┘
```

**用法二 TauriTavern / 手机**：TauriTavern 跑不了服务器插件，所以要在一台电脑上单独运行代理（Mac 酒馆工具或 `npm start`），打开「手机模式」（开放局域网、生成访问密码）。TauriTavern（手机或 Mac 上的）用链接安装面板，再连那台电脑的地址。聊天同步现在用 TauriTavern 自带的；CCST 自己的手机同步放在「其他」里，保留但不再开发。

```
 手机 TauriTavern + 面板 ──(同一 Wi-Fi，访问密码)──▶ 电脑上的独立代理 ──▶ Claude
                                                  （Mac 酒馆工具 / npm start，手机模式）
```

**用法三 服务器 / 云酒馆**：代理装在 Linux 服务器（一条命令或 Docker），酒馆在服务器上（可当插件装）或在别处连过来。安装脚本在 CI 的 Linux 上（systemd 和 nohup 两种）自动跑通，Docker 两个容器也在 CI 里起过；详见下面的章节。

```
 浏览器 / TauriTavern ──(访问密码，建议 HTTPS 或 SSH 隧道)──▶ 服务器上的代理（systemd / Docker）──▶ Claude
```

一键安装器的步骤见 [README 的「安装」](../README.md#安装5-分钟)；装好以后就是下面这些。


### 使用

#### 首次引导

第一次打开面板、酒馆还没连上 Claude 时，面板顶部出现三步引导（只给全新安装：酒馆已经连着 Claude、或设置里有用过的痕迹——连接过、改过地址 / 访问密码 / 思考深度——的老用户不会看到，哪怕代理暂时没开）：

1. **选来源**：本机代理（订阅 / API 密钥 / 其他后端）、Claude 官方、OpenRouter、其他中转，每项一句话说给谁用。
2. **连接**：选本机代理就是下面那张连接卡（启动代理 → 登录 → 一键连接）；选直连就告诉你酒馆「API 连接」里密钥填哪（密钥只填在酒馆自己的框里，CCST 不经手），选好 Claude 模型后自动往下走。
3. **完成**：这个来源下 CCST 能做什么、做不了什么（直连没有防丢回复和用量统计）；直连还会给推荐的缓存设置（config.yaml，可复制）。点「完成」收起。

「跳过引导」直接收起。想再看一遍：**其他 → 重新引导**。

1. 打开「扩展」里的 **CCST** 面板。没连上时面板只显示一张卡片，告诉你缺什么（代理没启动 / 没登录 / 酒馆还没接上）和唯一一个按钮（启动代理的说明 / 登录说明 / **一键连接**）；连好后卡片消失，出现状态栏和四个页。
   **一键连接**会做这几件事：把酒馆的 API 来源设成本代理、提示词后处理设为「无」，然后**新建并选中一个叫「CCST」的连接配置，模型是 Opus 4.6**（已经有「CCST」配置就更新它），并弹出提示请你到酒馆「API 连接」里核对来源、地址和模型。你原来的连接配置不动，不会被覆盖。
2. 选模型：面板「推理」页一键切 Opus 5.5 / Opus 4.6，或在「API 连接」的模型下拉框里选（Sonnet 5、Fable 5.1 等）。预设可以推荐模型（`extensions.claude_max.model`），切到这个预设时面板自动换过去；只换模型，不动代理地址（酒馆自己的「预设绑定连接」会连地址一起换，手机上会断）。
3. 开始聊天。

酒馆自带的「推理强度」保持「自动」，思考深度在面板里设置。「提示词后处理」要设为「无」，一键连接时会自动改好。

面板顶部一行状态栏：在线点 · 模型 · 走哪 · 按什么计费（如「本机代理 · 订阅」「Claude 官方 · API 密钥」「OpenRouter · OpenRouter 额度」「NanoGPT · 中转」）· 5 小时额度（只在走订阅时）；点一下打开「状态」页。「仅下一轮」加深生效时多显示「下一轮 高」。代理断了、没登录、访问密码不对时，状态栏下多一张提示卡；体检问题数显示在「体检」页的角标上。

**代理后端**（「设置 → 代理后端」）：代理用哪个服务跑聊天——订阅（默认）、Anthropic API 密钥、AWS Bedrock、Google Vertex AI、Anthropic 兼容网关、OpenRouter。选好填上需要的项，点「保存并切换」，从下一条回复起生效（正在写的不受影响，不用重启代理）。填的内容只发给代理（本机，或手机连 Mac 时带访问密码），存在代理那台电脑的 `data/backend.json`（只有本人可读，不进仓库）；密钥填过后只显示「已填」，不会再传回网页。缓存排布、防丢回复、用量统计对所有后端都生效；不是订阅时「状态」页不显示订阅额度，用量按后端分开，API 类后端显示估算花费（token 数 × 官方价，以账单为准）。

| 后端 | 要填 | 说明 |
| --- | --- | --- |
| 订阅 | – | 本机 Claude 登录（`npm run login`） |
| API 密钥 | `sk-ant-…` | 按 token 计费，缓存 1 小时。酒馆「API 连接」密钥栏填 `sk-ant-…` 的老办法在「订阅」后端下照样能用 |
| Bedrock | 区域；凭证三选一：Bedrock API 密钥 / AWS 配置名 / Access Key，都不填用本机默认 AWS 凭证 | 模型名自动换成 Bedrock 的（如 `us.anthropic.claude-opus-4-8`，前缀按区域 us / eu / apac，可改 global）。Mythos 在 Bedrock 上没有 |
| Vertex | GCP 项目 ID、区域（如 `global`）；先在代理电脑上 `gcloud auth application-default login`，或填服务账号 JSON 路径 | 旧模型自动换成 `@日期` 的名字。Mythos 在 Vertex 上没有 |
| 网关 | 地址（https，本机可 http）、令牌 | 需兼容 Anthropic Messages 接口，按 Bearer 令牌认证；模型名按官方 id 发 |
| OpenRouter | OpenRouter 密钥 | 走 `https://openrouter.ai/api`（OpenRouter 为 Claude Code 提供的 Anthropic 兼容接口），模型名换成 `anthropic/claude-opus-4.6` 这种 |

不会在后端之间自动切换：一个后端出错（或回复被安全机制截断）就报错，不换别的后端或模型重试。

**生成进度**：面板最上面那一行状态栏会跟着回复变化。发出消息后显示「思考中 12 秒」，出字后显示「写作中 1,234 字」，写完显示「完成 · 1,850 字 · 38 秒 · 缓存 94%」，约 6 秒后变回平时的模型 / 额度。回复补回、断线 / 恢复、换了模型、被截断这些提示，都用酒馆自己的弹窗（右上角）显示。

**要调的只有两样**：「推理」页的模型（Opus 5.5 / 4.6）和思考深度（自动 / 低 / 中 / 高 / 超高 / 最大 / 不思考，加「仅下一轮」）。其余都自动处理：

| 以前的开关 | 现在 |
| --- | --- |
| 会话续接、深度注入保持原位、世界书移到末尾、注入并进发言、预设后置条目提前 | 默认值 + 预设自带的推荐（切预设自动套用、切走恢复）；世界书和发言后注入由代理按每个聊天的实际变化决定挪不挪 |
| 思考模式 | 并进思考深度（「不思考」）；「始终思考」在「设置 → 思考」里 |
| 显示思考过程 | 跟随酒馆的「显示模型思维」 |
| 后台请求的思考深度 | 固定「低」 |
| 省电显示 | 手机和 TauriTavern 上自动开，电脑上关 |
| 体检弹出提示 | 只在打开「体检（实验）」后才会弹；同一类问题点掉两次就不再弹（「其他 → 体检（实验）」里照样列出，可一键恢复） |
| 身份模式、代理地址 | 设置页；脚本按钮并排、保存完整请求在「其他」 |

原来的开关都还在：思考相关的在「设置 → 思考」，缓存与上下文的在「设置 → 高级」（默认折叠），排查问题时用。

| 面板页 | 内容 |
| --- | --- |
| 推理 | 模型（Opus 5.5 / 4.6）、思考深度、「仅下一轮」 |
| 状态 | 最新回复的可靠检查（模型拒绝 / 被截断 / 空回复，只在出现时显示一行）、上一轮缓存命中和原因（只显示**当前聊天**的；这个聊天还没有回复时写「这个聊天还没有回复」，不会拿别的聊天的数据顶替）、缓存建议（直连时）、5 小时 / 7 天额度（点「刷新」查看，之后每条回复写完自动查一次，不会一直转圈）、用量（可折叠，默认折叠，标题上写近 7 天请求数）、一键把世界书设为常驻 |
| 设置 | 连接（本机代理地址）、代理后端、思考（思考模式、后台请求思考深度、显示思考过程、身份模式）、高级（折叠：缓存与上下文的开关） |
| 其他 | 主线以外的功能，每项一个折叠区、下面一句话说明：Mac 遥控（代理由 Mac 启动器运行时才出现）· 手机连接（局域网代理地址、访问密码）· 省电显示 · 性能诊断 · 脚本按钮并排 · 体检（实验，折叠，默认关：总开关打开后才检查字数、段数（按预设的段落计划）、镜头卡、界面代码大小、禁词、破折号、人称、选项格式、重复段落、隐藏设定关键词、角色卡检查；受预设和其他扩展影响，可能误报；只数真实回复，开场白不算）· 查看发给模型的请求（要先打开「保存最近一次完整请求」，没开时查看按钮是灰的，写明「先打开上面的开关，再聊一轮」）· 重新引导（直接是一个按钮）· 使用说明 |

**不走代理也能用**：酒馆里能用 Claude 的来源面板都认得——Claude 官方源（含反向代理）、OpenRouter、Electron Hub、NanoGPT、AI/ML API、CometAPI、自定义 OpenAI 兼容地址。「推理」页的模型切换和预设的按模型配置（`byModel`）在这些来源上照样生效，面板会换成各来源自己的模型名（比如 OpenRouter 上是 `anthropic/claude-opus-4.6`）；来源的模型列表里没有这个模型时只提示，不会偷偷换别的。Claude 官方源的下拉框缺新模型（酒馆 1.19 没有 Opus 5.5）时，面板自动补上（代理开着时按代理的模型列表补）。

- 酒馆没有 AWS Bedrock 来源，「Vertex AI」来源只接 Gemini：这两家的 Claude 只能经中转（自定义地址）接进来。
- 直连时「状态 → 缓存」给出这个来源的缓存建议。酒馆的 Claude 缓存设置（`claude.cachingAtDepth`、`claude.extendedTTL`）在酒馆目录的 `config.yaml` 里，启动时才读，网页改不了：面板给出要改的几行和「复制」按钮，改完重启酒馆。AI/ML API、CometAPI、自定义中转酒馆没有缓存设置。
- 直连时面板看不到上一轮缓存命中（酒馆不把用量传给网页），到 Anthropic / OpenRouter 后台看。

聊天框里输入 `/图分 1–5` 给最新一楼的配图打分（记在消息上，给逐楼报表用）。

### 省额度：让缓存生效

长对话里，大部分额度花在每轮重新读取整段聊天记录上；命中缓存时这部分只按约十分之一计费（Anthropic 的计费规则）。能不能整段命中取决于预设、世界书和其他扩展，下面是预计需要同时满足的条件：

1. 不用按楼层改写旧消息的正则（如「5 楼外只发摘要」）；
2. 世界书改为常驻，不按关键词触发（面板「状态」页可一键转换，会先备份）；
3. 深度注入提到系统提示词里（预设可写 `extensions.claude_max.inlineSystem: false` 自动设置）。

在一次实测的聊天里，三条都满足后缓存命中率从 46% 提高到 95%、每轮约省 43% 额度；别的预设、世界书和扩展组合没有逐一实测，效果只能当预计。没命中时，面板会写明原因。

做不到的时候代理会自己补救：按关键词触发、每轮变化的世界书块移到本轮消息开头（系统提示词里留一行固定说明；新聊天从第一轮起就这样做，不再先整段重写两轮来「学」），角色卡的深度 0 注入接到你的发言末尾，深度 3 以上的注入（「保持原位」模式下原本会并进旧消息、每轮挪位置）移到本轮发言前，分界点按实际发出的提示词计算，学到的规律跨代理重启保留。用真实聊天的连续楼层空跑检查（不调用模型）：两种深度注入模式下在这批聊天上读到约 96% 的缓存（别的聊天不一定）。代理重启后，CLI 会把它的环境信息补在第一轮的末尾、之后又变成中间消息，以前重启后的第二轮必定整段重写；现在把这段信息固定放在历史开头（按模型存一份在 `data/cli-context.json`，只有账号和环境信息，没有聊天内容），重启后第二轮起就能命中。缓存有效期是 1 小时（订阅走 Claude Code 的默认），两楼之间隔十几分钟也能命中。

### 更新与卸载

- **更新代理**：用 git 的在仓库里 `git pull`；下载 ZIP 的重新下载解压，在新文件夹里双击 `launcher/mac/首次安装.command`（桌面上的「酒馆工具」会自动改指向新文件夹，旧文件夹可以删）。然后在酒馆工具里选「重启酒馆」（没在生成回复时）。「检查状态」发现代理还在跑旧版本会提醒。装成酒馆插件的：在 `plugins/CCST` 里 `git pull`（或重新 `node plugins.js install`），重启酒馆。
- **更新面板**：酒馆「扩展」管理里更新 CCST；手机上的面板可以用「手机同步」一起更新。
- **卸载**：酒馆工具里关掉「开机自动启动」，选「关闭酒馆」，删掉仓库文件夹和桌面上的「酒馆工具」；「合盖不睡」装过的话先在菜单里卸掉（会删 `/etc/sudoers.d/claudemax-lid`）。装成酒馆插件的删掉 `plugins/CCST`。聊天记录在酒馆自己的数据里，不受影响。

### 直连时缓存与手机的限制

直连 Claude API / OpenRouter 时缓存排布、手机防丢回复、额度和用量统计、手机同步和遥控都要连本扩展的代理。直连 API 的缓存用酒馆自己的设置：`config.yaml` 里 `claude.cachingAtDepth`、`claude.extendedTTL`（1 小时）。


## 用法二 TauriTavern 与手机

TauriTavern 没有服务器插件，代理要单独跑在电脑上（下面的「Mac 一键安装」或「只跑代理」），手机连它的局域网地址，详见下面「手机」一节。想只用手机、不要电脑：改用 API 密钥直连（README「直连不跑代理」）。聊天同步用 TauriTavern 自带的；本章里 CCST 自己的手机同步、TT 守护等保留但不再开发。

手机是 root 过的安卓：可以另外装 [tt-root-module（TT 守护）](https://github.com/kcgoofee-jpg/tt-root-module)，自动备份并同步手机上 TauriTavern 的数据，出事能一键恢复。

### 连不上时看哪一条

面板的「连不上 CCST 代理」卡片按你用的环境给不同的步骤，每一步都是能点或能复制的：

| 你在哪用 | 卡片给什么 | 该做什么 |
| --- | --- | --- |
| 电脑浏览器（Chrome / Edge）里的本机酒馆 | 「下载一键安装」（Mac 是 zip，Windows 是 .bat）+ 复制链接 | 双击运行，装完重启酒馆；下载没反应就复制链接到浏览器地址栏 |
| TauriTavern（Mac / Windows 电脑） | 「下载 CCST（zip）」，用系统浏览器打开；不给一键安装 | Mac：解压后双击 `launcher/mac/首次安装.command`，以后用桌面「酒馆工具」；Windows：见下面「实验性」，没有经过实测的路；打不开链接就点「复制链接」 |
| TauriTavern / 酒馆在手机上 | 同上，加「去填地址和密码」 | 电脑上「酒馆工具 → 其他 → 手机 → 手机模式」拿地址和访问密码，手机面板「其他 → 手机连接」填好，点「重新连接」；同一个 Wi-Fi |
| 云服务器上的酒馆，用浏览器 / 手机远程打开 | 服务器安装命令（可复制）+ 本指南链接；不给安装器 | SSH 进服务器运行命令，见「用法三」；面板的地址填这台设备能访问到的，不能是 127.0.0.1 |
| 版本不一致（代理旧） | TauriTavern：只讲单独运行的代理；浏览器：按代理是插件还是单独运行分开讲 | 酒馆工具首页「1 重启代理」；更新代码后再重启 |

### 手机


0. 手机装 [TauriTavern](https://github.com/Darkatse/TauriTavern/releases)（安卓 apk），「扩展 → 安装扩展」填 `https://github.com/kcgoofee-jpg/CCST`。Mac 上先按[Mac 一键安装](#mac-一键安装)装好代理。
1. Mac 上菜单选「其他 > 手机 > 手机模式」（电脑模式 ↔ 手机模式切换）。它会生成一个访问密码，让代理接受局域网请求，并显示代理地址（`http://<Mac 的局域网 IP>:8901/v1`）和密码。
2. 手机 TauriTavern → CCST 面板「其他 → 手机连接」：「代理地址」「访问密码」分别填上，点「重新连接」。用「同步手机」同步过的话已经填好。
3. Mac 首次弹出「允许 node 接受传入连接」时点允许。

手机模式下后台有一个守护进程：Mac 不空闲睡眠（`caffeinate`），代理退出后 30 秒内自动重启，Mac 断网或局域网地址变了会发通知（Mac 通知中心，以及通过 adb 连着的手机）。手机上的面板每 20 秒探测一次代理，断线时提示、连回来后提示「已恢复」。切回电脑模式时守护一起停止。

**合盖不睡**（菜单「其他 > 手机 > 合盖不睡」，可选）：macOS 合盖就睡，`caffeinate` 挡不住，只有 `pmset -a disablesleep 1` 可以。安装时输一次 Mac 密码，写入 `/etc/sudoers.d/claudemax-lid`，只允许免密执行 `pmset -a disablesleep 0/1` 这两条命令；之后守护在手机模式下自动打开，并在这些情况下放开（合盖就睡）并通知：用电池且电量低于 25%、低电量模式、合盖 3 小时没有请求、切回电脑模式或守护退出。守护被强杀或死机时，下次启动时恢复。可在 `launcher/config.local` 设 `LID_BATTERY_FLOOR`、`LID_IDLE_HOURS`、`LID_AWAKE=0`。思路参考 [Sleepless](https://github.com/Aboudjem/Sleepless)、[Awake](https://github.com/Koomook/awake)。合盖运行会发热，开着时别装进包里。

**同步手机**（其他 > 手机 > 同步手机，需要 adb 和手机 root）：同步中心 ↔ 手机 TauriTavern 双向同步。同步中心是这台 Mac 的 TauriTavern（`launcher/config.local` 里 `SYNC_HUB=tt`）或电脑 SillyTavern（`SYNC_HUB=st`，不写时有酒馆就用它）。同步聊天、角色卡、世界书、预设、头像、背景、生图图片、主题和快速回复，角色卡标签按名字合并（只加不删）；第三方扩展只从电脑推到手机（git 版本不同时），换下来的旧文件夹收进存档（手机 `data/_cm_archive/`，Mac TT 的进 `backups/`，每个扩展只留最新一份）。从不删除文件，被覆盖的先存进 `backups/`。

一次同步分几步：

1. **看两边**：Mac TT、手机 TT 开没开、在不在生成回复，代理忙不忙，手机上的 TT 守护在不在恢复备份（在恢复就不同步）。
2. **预览**，分三组：
   - 自动：只有一边改过的，直接做；
   - 要你选：两边都改过的聊天（用 Mac 的 / 用手机的 / 两份都留）、两边都改过的其他文件、API 和预设设置不一样（Mac / 手机 / 跳过；连哪个地址各自保留）、API 密钥（两边互补：只加缺的、不启用，各自正在用的不变 / 跳过）、扩展没设上游、上次恢复没做完、要关掉正在用的 TT（现在关 / 等生成完 / 取消）；
   - 跳过：判断不了的（文件名只差大小写、手机上的扩展比电脑新或分叉……），列出来不动。
3. 你选完，写手机之前让 TT 守护先存一份快照（没装就跳过，会说一声）。
4. 执行，然后再比一遍两边，列出结果；原来开着的 TT 重新打开。

```
  自动（只有一边改过，不用问）
    → 手机 1 个：都市.json
    ← Mac TT 1 个：Bob - 2026-09-26
  要你选
    a 聊天「Alice - 2026-09-20」两边都改过（Mac TT 多 1 楼，手机多 2 楼；手机的较新）
    b API 和预设设置两边不一样（Mac TT「日常」，手机「省额度」；手机的较新）
    c API 密钥两边不一样（Mac TT 缺 1 条，手机缺 1 条）
    d 要关掉手机上的 TT（在生成回复）和这台 Mac 上的 TT（开着会把旧内容存回去；同步完再打开）
```

手机上 CCST 面板里的「同步手机」（手机遥控）不问问题：两边都改过的用较新的、另一份进备份（聊天多出的楼另存「冲突副本」），API 设置和密钥不动、只列出来，TT 守护在恢复或上次恢复没做完时不同步。手机模式开着时，同步会把手机的代理地址对准 Mac 现在的 IP，并让手机「自定义」来源正在用的密钥是 Mac 的访问密码。插线时可以顺手开无线调试，之后同一 Wi-Fi 不插线也能同步。

**TT 守护**（其他 > TT 守护，需要 root + KernelSU）：[tt-root-module](https://github.com/kcgoofee-jpg/tt-root-module)，手机上的数据保护模块：自动备份、实时副本、一键恢复、保活。安装和更新都在手机 KernelSU → 模块 → TT 守护 里做（菜单只提示有新版本，从不替你装）。菜单里：看状态（版本、上次备份、有没有新版本）；立即拉一次备份到电脑、电脑自动拉备份开 / 关（这两项要把模块仓库 clone 到本仓库同级目录，用它的 `pc/pull-backups.sh`、`pc/install-mac.sh`）；从备份恢复（选一份 → 确认；TT 要先在手机上关掉，电量低于 15% 时模块会拒绝）。

**本机 TT 导入**（菜单「其他 > 本机TT导入」，测试用）：电脑 SillyTavern → 同一台 Mac 上的 TauriTavern，一键导入聊天、角色卡（连同标签）、世界书、预设、图片和第三方扩展，可选连扩展设置（柏宝绘、MVU、小白X、正则、CCST）和当前预设一起导入。单向：TT 独有的文件保留，TT 上更新过的不覆盖，被覆盖的先备份。

**回复不会再丢**：手机上的 TauriTavern 退到后台时，系统会暂停它的网页，收到的回复可能来不及存；中途被关掉也会断在一半。现在每次请求带一个「槽位」（聊天、楼层、第几个回复和你那句话的哈希，不含内容），代理写完后把回复按槽位存在内存里（不落盘，最多 40 个聊天，6 小时）。App 中途断开时代理照样写完；你按「停止」时面板会通知代理停下并丢掉这条，不会再补回。重新打开聊天、切回 App 或连回代理时，只有这几种情况会补回：最后一楼是空的或「...」、写到一半断了（面板在写的过程中做了标记）、App 在存盘前就被关了（聊天停在你的发言上，补一楼上去）。你编辑过、删掉或按停止的回复一律不动。

**手机遥控 Mac**（面板「其他 → Mac 遥控」，代理由 Mac 启动器运行时才出现）：看 Mac 的状态（模式、地址、电量、盖子、合盖不睡、本地生图、正在写的回复、最近的错误），按钮只有这几个：重启代理（有回复正在写时拒绝）、同步手机、看日志最后几十行（带「复制」按钮，复制不了时自动全选文字）。「同步手机」只在 TauriTavern 里、手机模式下出现：TauriTavern 自带同步和备份，建议用它；电脑酒馆和 TT 之间的同步还没测试过，可能有问题，所以确认框里先写明这一点，按钮叫「仍要同步（未测试）」，点了才照原流程做（TT 会先关再开）。「本地生图」「合盖不睡」的按钮不在面板里了，去 Mac 上的「酒馆工具」菜单操作（代理的遥控接口还保留）。走现有代理和访问密码，不能执行任意命令；每次操作记进启动器日志，并在 Mac 上弹通知。

其他设备的请求必须带访问密码（`Authorization: Bearer <密码>` 或 `X-Claude-Max-Key`），本机不需要。没开手机模式时，就算代理绑到 `0.0.0.0` 也会拒绝所有局域网请求。不要在公共 Wi-Fi 开启，密码不要外传：拿到密码的人用的是你的订阅。手动启动时对应的环境变量是 `CLAUDE_SUBSCRIPTION_HOST=0.0.0.0`、`CLAUDE_SUBSCRIPTION_LAN_KEY=<密码>`。

## 用法三 服务器与 Docker

把代理（和酒馆）放在一台 Linux 服务器上，自己用手机或电脑的浏览器访问。订阅登录、API 密钥、Bedrock、Vertex、OpenRouter 都能用。

### 先准备什么

| 需要 | 说明 |
| --- | --- |
| 一台 Linux 服务器 | 最好有 systemd（Ubuntu / Debian / Fedora 等都有）。没有 systemd 也行，脚本会改用 `nohup`，但服务器重启后要重新运行一次脚本 |
| 安装脚本方式 | Node 18+（推荐 22）、git、npm；不需要 root |
| Docker 方式 | Docker 和 Docker Compose v2；不需要装 Node |
| Claude 订阅或别的后端 | 订阅需要在**一台有浏览器的电脑**上授权一次（服务器没有浏览器，见下面「登录」） |
| 一台有浏览器的设备 | 用来打开酒馆；服务器上的酒馆可以用 SSH 隧道或 HTTPS 域名访问 |

两种部署选一个：

- **方式一 安装脚本（酒馆和代理在同一台机器）**：最省事。可以装成酒馆插件（代理随酒馆启动，本机连接，不用访问密码），也可以装成独立代理（酒馆在别处连过来）。
- **方式二 Docker（酒馆一个容器、代理一个容器）**：隔离干净，一条命令起两个。

### 方式一：安装脚本

```bash
curl -fsSL https://raw.githubusercontent.com/kcgoofee-jpg/CCST/main/deploy/install.sh | sh
```

可以重复运行（相当于更新）。它会：检查环境 → 把 CCST 下载到 SillyTavern 旁边（没找到酒馆就是 `~/CCST`）→ `npm install` → 生成随机访问密码存到 `~/.config/ccst/env`（权限 0600，**只在最后显示一次**）→ 用 `systemd --user` 启动代理。**默认只监听 127.0.0.1**，不改系统设置。

常用选项（写在 `sh -s --` 后面，或本地 `sh deploy/install.sh ...`）：

| 选项 | 作用 |
| --- | --- |
| `--dir DIR` / `--port N` | 安装目录（路径不能有空格）/ 端口，默认 8901 |
| `--token-prompt` | 运行时粘贴 Claude 订阅令牌（不回显，`curl \| sh` 也能用），见「登录」 |
| `--token-from-env` | 从环境变量 `CLAUDE_CODE_OAUTH_TOKEN` 读令牌（无人值守用） |
| `--public` | 监听 `0.0.0.0`，见「安全清单」。访问密码照样强制，脚本会再打一次警告 |
| `--local` | 改回只监听 127.0.0.1 |
| `--dry-run` / `--no-service` | 只打印会做什么 / 只装文件不启动 |
| `--uninstall` | 停止并删掉服务和配置（`--remove-files` 连安装目录一起删；登录信息不动） |

想让服务在你退出 SSH 后继续运行：`sudo loginctl enable-linger $USER`。管理：`systemctl --user status|restart|stop ccst-proxy`，日志 `journalctl --user -u ccst-proxy -e`。

**酒馆怎么连**：

- 服务器上已有酒馆，想让代理随酒馆启动：在酒馆 `config.yaml` 设 `enableServerPlugins: true`，然后在酒馆目录运行 `node plugins.js install https://github.com/kcgoofee-jpg/CCST`（和脚本装的独立代理二选一，别占同一个端口）。面板从酒馆「扩展 → 安装扩展」填 `https://github.com/kcgoofee-jpg/CCST` 装。
- 独立代理：酒馆「API 连接」选「自定义」，地址 `http://127.0.0.1:8901/v1`（酒馆在同一台服务器）。酒馆在别的机器时地址换成能访问到代理的地址，API 密钥栏填访问密码。

### 方式二：Docker

`deploy/docker-compose.yml` 起两个容器：酒馆（官方镜像 `ghcr.io/sillytavern/sillytavern`）和 CCST 代理（用仓库里的 `Dockerfile` 现场构建）。

```bash
git clone https://github.com/kcgoofee-jpg/CCST && cd CCST
echo "CCST_ACCESS_KEY=$(openssl rand -hex 24)" > deploy/.env     # 访问密码，别外传
docker compose -f deploy/docker-compose.yml up -d --build
```

- 酒馆和代理是两个容器，代理不能当酒馆的服务器插件。酒馆用自定义端点连代理：地址 `http://ccst:8901/v1`（`ccst` 是 compose 里代理容器的名字），API 密钥栏填访问密码。
- 浏览器里的面板不能用 `ccst` 这个名字（那是容器内部的名字）。所以面板「其他 → 手机连接」里：**代理地址**填浏览器能访问到的地址（SSH 隧道就是 `http://localhost:8901/v1`）、**访问密码**填同一个密码、**酒馆侧地址**填 `http://ccst:8901/v1`，再点「一键连接」，酒馆那边就会自动填上容器内部地址。
- 两个端口默认只映射到宿主机的 `127.0.0.1`（酒馆 8000、代理 8901）。数据在卷里：`ccst-data`（后端设置、用量、Claude 登录信息）和 `st-config` / `st-data` / `st-extensions`（酒馆的设置、聊天、扩展）。删容器不会丢，删卷（`down -v`）会。
- 面板：打开酒馆后「扩展 → 安装扩展」填 `https://github.com/kcgoofee-jpg/CCST`。
- 只想要代理、不要酒馆容器：`docker compose -f deploy/docker-compose.yml up -d --build ccst`；或 `docker run -d -p 127.0.0.1:8901:8901 -v ccst-data:/data -e CLAUDE_SUBSCRIPTION_LAN_KEY=<密码> ccst`（镜像要先 `docker build -t ccst .`，还没有发布到镜像仓库）。

### 登录（服务器没有浏览器）

订阅登录必须在浏览器里授权。三种办法，按推荐顺序：

**① 在有浏览器的电脑上生成长期令牌（推荐）。** 电脑上装好 Claude Code（`npm i -g @anthropic-ai/claude-code`），运行：

```bash
claude setup-token
```

浏览器里授权后，终端会打印一串以 `sk-ant-oat01-` 开头的令牌（只显示一次，需要 Claude 订阅）。把它交给服务器：

- 安装脚本：`sh deploy/install.sh --token-prompt`，把令牌粘贴进去（不回显、不会打印出来，存进 `~/.config/ccst/env`，权限 0600）。无人值守则 `CLAUDE_CODE_OAUTH_TOKEN=... sh deploy/install.sh --token-from-env`。
- Docker：在 `deploy/.env` 加一行 `CLAUDE_CODE_OAUTH_TOKEN=<令牌>`，并把 compose 里 `CLAUDE_CODE_OAUTH_TOKEN` 那行的注释去掉，`docker compose ... up -d` 重建。

注意：这种令牌只有调用模型的权限，不能用 Claude Code 的 Remote Control 等需要完整登录的功能；对 CCST 没影响。令牌等同于你的订阅，不要贴进聊天、截图或提交到仓库。

**② 在服务器上走网址授权。** 安装目录运行 `npm run login`（Docker：`docker compose -f deploy/docker-compose.yml exec ccst node bin/claude-cli.js auth login`）。它会打印一个网址：在你自己电脑的浏览器打开、授权，把网页给的授权码粘贴回终端（提示 `Paste code here if prompted`）。登录信息存在 `~/.claude`（Docker 里是 `ccst-data` 卷），只需一次。Claude 现在没有「设备码」登录方式，所以用这条网址加授权码。

**③ 不用订阅。** API 密钥、OpenRouter、Bedrock、Vertex、网关：把下表的环境变量加到 `~/.config/ccst/env`（一行一个 `名字=值`，不加引号，`systemctl --user restart ccst-proxy`）或 compose 的 `environment`，也可以用访问密码连上代理后在面板「设置 → 代理后端」里填。

| 后端 | 变量 |
| --- | --- |
| Anthropic API 密钥 | `CLAUDE_SUBSCRIPTION_BACKEND=apikey`、`CLAUDE_SUBSCRIPTION_API_KEY` |
| OpenRouter | `CLAUDE_SUBSCRIPTION_BACKEND=openrouter`、`CLAUDE_SUBSCRIPTION_OPENROUTER_KEY` |
| AWS Bedrock | `CLAUDE_SUBSCRIPTION_BACKEND=bedrock`、`CLAUDE_SUBSCRIPTION_AWS_REGION`，再加 `CLAUDE_SUBSCRIPTION_BEDROCK_TOKEN`，或 `..._AWS_ACCESS_KEY_ID` + `..._AWS_SECRET_ACCESS_KEY`（+ `..._AWS_SESSION_TOKEN`）、`..._AWS_PROFILE` |
| Google Vertex | `CLAUDE_SUBSCRIPTION_BACKEND=vertex`、`CLAUDE_SUBSCRIPTION_VERTEX_PROJECT`、`..._VERTEX_REGION`、`..._VERTEX_CREDENTIALS`（服务账号 JSON 的路径，Docker 里放进 `/data`） |
| Anthropic 兼容网关 | `CLAUDE_SUBSCRIPTION_BACKEND=gateway`、`CLAUDE_SUBSCRIPTION_GATEWAY_URL`、`CLAUDE_SUBSCRIPTION_GATEWAY_TOKEN` |

设了 `CLAUDE_SUBSCRIPTION_BACKEND` 以后它优先于面板里选的。API 密钥类后端按 token 计费，用量页显示的是估算花费。设了后端，`CLAUDE_CODE_OAUTH_TOKEN` 会被忽略。

### 从手机或电脑浏览器访问

酒馆默认只开在服务器本机，从自己的设备访问有两条路：

**A. SSH 隧道（最简单，不用域名，不对外开放任何端口）**：在自己的电脑上运行

```bash
ssh -N -L 8000:127.0.0.1:8000 -L 8901:127.0.0.1:8901 用户@服务器
```

然后浏览器打开 `http://localhost:8000`。面板的代理地址保持 `http://127.0.0.1:8901/v1`（隧道把它接到服务器）。手机可以用 Termius、Blink、JuiceSSH 等 App 做同样的端口转发，或者改用 B。

**B. HTTPS 域名（手机最方便）**：给服务器配一个域名，前面加 Caddy（自动申请证书）。`/etc/caddy/Caddyfile`：

```caddyfile
st.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

要点：

- 酒馆**必须**先设好自己的访问保护（见下），不然域名一开任何人都能进。
- **代理装成酒馆插件时（方式一）**：只暴露酒馆域名就够了。面板发现浏览器连不到 `127.0.0.1:8901`，会自动改走酒馆自己的插件路由，代理不用对外。
- **Docker 两个容器时**：浏览器里的面板要直接访问代理，代理也要有 HTTPS 域名：Caddyfile 再加
  ```caddyfile
  ccst.example.com {
      reverse_proxy 127.0.0.1:8901
  }
  ```
  面板「代理地址」填 `https://ccst.example.com/v1`、访问密码填代理的密码，「酒馆侧地址」填 `http://ccst:8901/v1`。代理默认只接受 localhost 页面发来的浏览器请求，要让它接受你的酒馆域名：给代理容器设 `CLAUDE_SUBSCRIPTION_ALLOWED_ORIGINS=https://st.example.com` 和 `CLAUDE_SUBSCRIPTION_ALLOWED_HOSTS=ccst,ccst.example.com`（compose 里 `ALLOWED_HOSTS` 已有 `ccst`，在后面加上域名；`ALLOWED_ORIGINS` 那行取消注释，重启容器）。Docker 端口映射会让代理看到的来源不是「本机」，所以这条路上访问密码照样强制。
- **反向代理和访问密码**：代理把"来自 127.0.0.1、且不带 `X-Forwarded-For` / `Forwarded` / `X-Real-IP` / `CF-Connecting-IP` 头"的请求当作本机（酒馆插件、localhost 上的面板都是这样，不需要密码）。Caddy、nginx、Cloudflare 转发时都会加这些头，所以经过它们的请求照样要访问密码，不会因为反代在同一台机器上就绕过。如果你的反代不加这类头，设 `CLAUDE_SUBSCRIPTION_REQUIRE_KEY=1`，代理对所有请求（包括本机）都要密码；此时酒馆插件方式不能用（插件不带密码），只能走独立代理加自定义端点。
- 用了 Caddy，代理继续监听 127.0.0.1，不要再加 `--public`。

### 安全清单

装好之后对一遍：

1. **代理只听 127.0.0.1**（默认）。`ss -ltn | grep 8901` 应该看到 `127.0.0.1:8901`，不是 `0.0.0.0:8901` 或 `*:8901`。
2. **用了 `--public` / 改了端口映射才是开放的**：拿到访问密码的人用的就是你的订阅，而且端口是明文 HTTP。防火墙（ufw / 云厂商安全组）只放行你自己的 IP，前面加 HTTPS。代理对非本机的请求一律要访问密码，没设密码就拒绝，脚本和 compose 都会生成 / 强制设置。
3. **酒馆自己的保护**（酒馆 `config.yaml`，改完重启酒馆；Docker 里在 `st-config` 卷的 `config.yaml`，可以 `docker compose -f deploy/docker-compose.yml exec sillytavern vi config/config.yaml`）：
   - `listen: true` 之前，先把 `whitelistMode: true` 和 `whitelist`（IP 白名单，默认只有 `127.0.0.1`、`::1`）配好；Docker 镜像本身会监听所有网卡，靠白名单和端口映射（只映射到 127.0.0.1）保护。
   - `basicAuthMode: true`，并把 `basicAuthUser` 的用户名和密码改掉（默认的 `user` / `password` 等于没设）。
   - 多人用：`enableUserAccounts: true`，每个人自己的账号，管理员设密码。
   - 用域名访问时开 `hostWhitelist`，把你的域名加进 `hosts`；如果开了 `privateAddressWhitelist`，要把酒馆到代理的地址（Docker 的内网网段）加进 `allowedRanges`，不然酒馆连不上代理。
   - `securityOverride` 保持 `false`。
4. **访问密码**：只存在 `~/.config/ccst/env`（0600）或 `deploy/.env`（已在 `.gitignore`）；脚本只在第一次生成时显示一次。泄漏了就改掉那一行，重启代理，再到酒馆 API 连接和面板里改成新的。
5. **令牌和 API 密钥**：同样只放在上面那些文件里，别贴进聊天、别提交到仓库。脚本不会把令牌打印出来。
6. **登录信息**在 `~/.claude`（或 Docker 的 `ccst-data` 卷），等同于订阅，备份时别传到公开的地方。

### 出问题怎么办

- **`curl http://127.0.0.1:8901/status` 没反应**：systemd 看 `journalctl --user -u ccst-proxy -e`；nohup 看 `~/.config/ccst/proxy.log`；Docker 看 `docker compose -f deploy/docker-compose.yml logs ccst`。常见原因：`npm install` 没装全（别加 `--omit=optional`，Claude CLI 在可选依赖里）、端口被占。
- **脚本说「没有可用的 systemd --user」**：SSH 进去的会话没有用户总线（常见于 `su`、`sudo -i`）。用正常登录的 SSH 会话，或 `sudo loginctl enable-linger $USER` 后重新登录；不想折腾就用 nohup（脚本自动选），服务器重启后重新运行脚本。
- **退出 SSH 后代理停了**：`sudo loginctl enable-linger $USER`。
- **面板提示 401「访问密码不对」**：面板「其他 → 手机连接」的访问密码和服务器 `~/.config/ccst/env` 里的 `CLAUDE_SUBSCRIPTION_LAN_KEY`（Docker 是 `CCST_ACCESS_KEY`）不一致。
- **403「代理不接受用……这个地址访问」**：用了代理不认识的名字访问它（域名、Docker 的 `ccst`），把它加进 `CLAUDE_SUBSCRIPTION_ALLOWED_HOSTS`（compose 示例已经加了 `ccst`）。
- **面板连不上代理，但酒馆本身能聊**：浏览器访问代理的地址和酒馆页面的来源不被允许。用隧道时保持 `localhost`；用域名时设 `CLAUDE_SUBSCRIPTION_ALLOWED_ORIGINS`（见上）。
- **登录后提示还是没登录**：令牌过期或被撤销，重新 `claude setup-token`；或确认环境变量名是 `CLAUDE_CODE_OAUTH_TOKEN`，改完重启代理。
- **酒馆容器连不上代理**：`docker compose -f deploy/docker-compose.yml exec sillytavern node -e "fetch('http://ccst:8901/status',{headers:{Authorization:'Bearer <密码>'}}).then(r=>console.log(r.status))"` 应该打印 200；401 是密码不对，403 是名字没加进 `ALLOWED_HOSTS`，连接被拒则是代理没起来。
- 到 [issue #18](https://github.com/kcgoofee-jpg/CCST/issues/18) 反馈其他问题。


## 常见问题

**双击脚本提示「无法验证开发者」**：在文件上右键 → 打开 → 再点「打开」，只需一次（或「系统设置 → 隐私与安全性 → 仍要打开」）。用 `git clone` 下载的不会有这个提示。

**Opus 5.5 第一轮就报「套取推理过程」（reasoning_extraction）**：预设或角色卡的世界书里有要求把思考写进正文的条目（常见写法：「用全英文输出 `<draft_notes>`」「先在 `<thinking>` 里思考」）。本扩展用原生思考，把那条关掉就行；面板发送前会指出是哪一句。想看写在正文里的思维链，就在「推理」页切到 Opus 4.6 并把思考关掉。

**Xcode 更新后脚本报「You have not agreed to the Xcode license」**：酒馆工具会自动改用「命令行工具」里的 git / python3，照常能用；有空时在终端运行 `sudo xcodebuild -license accept` 同意一次。

**面板显示「连接不到代理」**：原版酒馆确认 `enableServerPlugins: true` 并已重启；单独运行时确认 `npm start` 在运行。

**「未登录」或聊天中途认证失败**：在代理目录运行 `npm run login`（用运行酒馆的同一个系统用户），`npm run auth` 查看状态。

**「Failed to load @anthropic-ai/claude-agent-sdk」**：在代理目录重新 `npm install`（不加 `--omit=optional`），然后重启。

**1M 模型只有 200k 上下文**：部分套餐要开通额外用量才能用 1M。失败后代理会改用普通版一小时再重试。

**模型列表是空的**：再点一次一键连接，或在浏览器打开 `http://127.0.0.1:8901/status` 看代理状态。


## 高级：环境变量、接口、预设字段

| --- | --- | --- |
| `CLAUDE_SUBSCRIPTION_PORT` | `8901` | 监听端口（改了要同步改面板「设置 → 连接」里的代理地址（手机上是「其他 → 手机连接」）） |
| `CLAUDE_SUBSCRIPTION_HOST` | `127.0.0.1` | 监听地址。改成 `0.0.0.0` 会让同一网络的任何人都能用你的订阅 |

| `CLAUDE_SUBSCRIPTION_NO_UI_INSTALL` | – | `1` 表示不自动安装面板 |
| `CLAUDE_SUBSCRIPTION_BACKEND` | – | 代理后端：`subscription` / `apikey` / `bedrock` / `vertex` / `gateway` / `openrouter`，优先于面板里选的 |
| `CLAUDE_SUBSCRIPTION_API_KEY` 等 | – | 后端的各项，优先于 `data/backend.json`：`_API_KEY`、`_AWS_REGION`、`_AWS_PROFILE`、`_BEDROCK_TOKEN`、`_AWS_ACCESS_KEY_ID`、`_AWS_SECRET_ACCESS_KEY`、`_AWS_SESSION_TOKEN`、`_BEDROCK_PREFIX`、`_VERTEX_PROJECT`、`_VERTEX_REGION`、`_VERTEX_CREDENTIALS`、`_GATEWAY_URL`、`_GATEWAY_TOKEN`、`_OPENROUTER_KEY`（都以 `CLAUDE_SUBSCRIPTION` 开头，不传给 CLI）。shell 里的 `ANTHROPIC_API_KEY`、`CLAUDE_CODE_USE_BEDROCK` 这类会被清掉，不会悄悄改变计费 |

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/status` | SDK 和登录状态 |
| GET | `/v1/models` | 模型列表 |
| GET | `/v1/usage/quota` | 订阅额度（非订阅后端返回 `notSubscription: true`） |

| GET | `/v1/usage/stats` | 用量统计和上一轮缓存分析 |
